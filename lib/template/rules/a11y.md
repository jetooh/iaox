# IAOX — Acessibilidade (WCAG 2.2 AA)

Regra auto-carregada. Define o padrão de acessibilidade de toda UI do ecossistema.
Executada pelo `@a11y`.

## Princípio

Acessibilidade não é opcional nem um extra no fim — é parte do "correto". Toda
interface é usável por teclado, leitor de tela e com contraste adequado. Padrão da
casa: **WCAG 2.2 nível AA** (também exigência legal em 2026 — EAA/ADA).

## Regras invioláveis

1. **Operável por teclado:** todo fluxo funciona sem mouse, com **foco visível** e
   ordem lógica; nada de armadilha de foco.
2. **Semântica primeiro:** use o elemento HTML certo (`button`, `a`, `label`,
   landmarks, headings hierárquicos). ARIA só quando o nativo não resolve — **ARIA
   errado é pior que nenhum**.
3. **Nome acessível:** imagens com `alt`, inputs com `label`, ícones/botões com nome;
   conteúdo dinâmico com `aria-live`.
4. **Contraste:** texto ≥ 4.5:1 (3:1 para grande). **Nunca** comunique só por cor.
5. **Respeite o usuário:** `prefers-reduced-motion`, alvos de toque adequados, zoom.

## Testes

Integre **axe-core** aos testes (E2E via `@axe-core/playwright` e/ou unit via
`vitest-axe`) nas telas principais. Automação cobre ~40% — o `@a11y` complementa
com teclado + leitor de tela manual.

## Ship gate

Uma feature com UI só é `Done` **sem violações críticas/sérias** de a11y e com o
fluxo principal navegável por teclado. O `@qa` inclui a11y no SCORE (dimensão
UX/Acessibilidade); o `@a11y` valida.

## Relação com outros agentes

- `@ux` decide o visual; o `@a11y` garante que é acessível.
- `@i18n` cuida do idioma dos textos (pt-BR) — inclusive mensagens de erro de forms.
- `@e2e` roda os testes de a11y junto dos E2E.

## Gatilhos

Aplica sempre que houver UI: telas, componentes, formulários, navegação — roteie ao
`@a11y` antes de fechar a feature.
